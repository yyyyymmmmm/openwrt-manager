# 原生系统文件管理：计划任务

当前适配系统→计划任务。原生 SwiftUI 表单和文本编辑器，不加载 LuCI 网页。以下为协议及源码实现范围，尚未运行本增量测试或在用户路由器写入。

## 协议依据

- [LuCI crontab.js](https://github.com/openwrt/luci/blob/master/modules/luci-mod-system/htdocs/luci-static/resources/view/system/crontab.js)：`file.read/write` 的固定路径 `/etc/crontabs/root`，保存后固定 `/etc/init.d/cron reload`。
- [LuCI ACL](https://github.com/openwrt/luci/blob/master/modules/luci-mod-system/root/usr/share/rpcd/acl.d/luci-mod-system.json)：`luci-mod-system-cron` 的文件读写和固定重载命令权限。
- [rpcd file.c](https://github.com/openwrt/rpcd/blob/master/file.c)：`read`、`write`、`list`、`exec` 及文件路径/命令 ACL。`file.write` 会截断后写入，不是条件写入，也不是 UCI 事务。

上游 master 不保证与所有固件一致，App 保留实际错误。部分受限账户只有写文件权限，未被允许通过 `file.exec` 重载；这时保留文件保存事实并明确显示重载权限错误，不宣称任务生效。

## 原生路径

系统→计划任务→格式与执行说明；任务文本→草稿→原文及将保存的全文→明确确认→重新检查写权限→重读原文并比对→`file.write`→重读逐字核对→固定重载→实际退出码、stdout、stderr 或权限/网络错误。单独重载会再次比对当前内容，不写文件。

root 文件读取成功才显示文本；明确空字符串代表文件为空。NOT_FOUND 在 ubus 中也可能表示方法不存在，不能直接推定任务文件缺失。因此只有 `/etc/crontabs` 目录列表实际成功、记录格式正确且没有 root 条目时，才提供创建流程；目录拒绝访问、目录不存在或 root 文件实际存在但不可读时保留原始读取错误。

编辑保留注释、空行和固件语法；只将 CRLF 换成 LF，并补齐非空文件末尾换行。拒绝 NUL、孤立 CR 和超过 64 KiB 的内容。创建使用 0600；rpcd 对已有文件保留其权限。没有把草稿文本嵌入 shell 或命令参数，执行命令固定为 cron reload。内容仅通过文件写入 API 提交，实际定时命令由固件 cron 在对应时间执行。

没有任务语法或执行成功的虚构校验。说明明确使用路由器时区、不增加用户名字段、语法扩展以固件为准；cron 重载退出码 0 不能证明每行有效。可以进入实际发现的 cron 启动项和系统日志继续核对。

## 冲突、错误与恢复边界

- 预览绑定当前连接；写操作使用全局互斥锁，并在 UCI 等待确认时禁用。切换路由器会重建页面，其他配置的草稿不受本页保存影响。
- 提交前对照完整原文，发现其他管理员修改则拒绝写入；保存后必须内容一致才报告“保存并重读一致”。固件没有比较后原子替换 API，核对与写入之间仍有竞态。应避免多端同时编辑。
- 文件写入、重读网络错误或内容不一致时，文件可能已变更；不自动重试，不自动恢复旧内容覆盖其他管理员修改。保留草稿并要求先重新读取。
- 重读一致后再请求 cron 重载；重载拒绝、非零退出码、超时分别呈现。保存成功但重载失败不伪装为整个流程失败，也不声称任务已执行。
- 刷新可选择保留草稿或明确放弃；保留后使用最新文件作为比较基础，由用户手工核对/合并后重新预览。离开有未保存内容时要求确认。
- 从格式说明或日志返回不会自动重读覆盖草稿；首次读取若因导航被取消，返回后继续读取并保留已出现的草稿。
- 没有 UCI 超时回滚。恢复需要用户编辑、预览、明确提交。任务执行需在到期后核对日志和命令实际结果。
