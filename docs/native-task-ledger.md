# 原生 OpenWrt 任务台账

这份台账把一项用户功能定义为一条可以从入口走到真实结果的纵向任务。`TASKS.md` 只在对应任务的完成门槛全部满足后勾选；源码存在、页面能打开、Release 能编译、静态菜单被发现，都不能单独把任务标为完成。

## 完成门槛

每张任务卡必须记录并验证：

1. 完整用户路径：一级入口、子菜单、子子菜单、详情、编辑和返回路径。
2. 真实读取协议：ubus、固定受控命令或受控文件接口；解析失败、缺失和无权限分别呈现。
3. 真实写入协议（适用时）：字段校验、变更预览、ACL、并发检查、apply/confirm、超时或失败恢复、应用后回读。
4. 原生交互：加载、空结果、错误、只读账户、未安装组件和固件能力差异均有页面结果。
5. 证据：协议/解析测试、模拟器逐层点击记录，以及与任务范围匹配的真实路由器只读或写入验证。
6. 文档：记录实际覆盖范围和仍未覆盖的字段，不把通用 UCI 编辑器当作插件专用业务完成。

## 状态

`未开始` → `开发中` → `代码完成` → `协议通过` → `模拟器逐层通过` → `真实只读通过` → `真实写入通过` → `完成`

某任务不需要写入时，跳过 `真实写入通过`，但必须记录原因。任何中间状态都不能在 `TASKS.md` 勾选。
